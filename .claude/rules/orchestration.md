# LifeCommit — только для Claude

Общие правила проекта — `AGENTS.md`. Здесь то, что делает только Claude: делит работу, ревьюит, накатывает миграции и пушит.

## Задания и сессии

- Фичу на несколько клиентов делю на задания Codex по платформам (мини-апп и сервер, iOS/Mac, Android); контракт API (`docs/mobile.md`) фиксирую до заданий. Пуш — когда готовы и проверены все части.
- В задании — цель и зачем, а не только задача. Ключевые утверждения отчёта Codex перепроверяю сам.
- В репозитории бывают и другие сессии Claude. Перед пушем в `main` — `ListAgents`; если правки пересекаются, договариваюсь через `SendMessage`, после пуша говорю им.
- Своя копия для Codex или для себя: `.dev.vars` агентам закрыт целиком (чтение, `ls`, `test -f`, даже `cp`; «ок» в чате запрет не снимает). Заранее прошу владелицу выполнить `! cp ~/work/LifeCommit/.dev.vars ~/work/<копия>/.dev.vars` (тишина — успех). Проверка без чтения: `git -C <копия> status --short --ignored | grep dev.vars`.
- Перед полным дизайном — живой каталог разных вариантов (скилл `prototype`) на холсте или отдельной живой страницей, где видно движение и прокрутку.

## Ревью перед пушем

- Фича — `/lc-review` (доступ, ошибки, тесты, интерфейс мини-аппа; серьёзное проверяет скептик) вместе со встроенным `/code-review`.
- Правка `auth.ts`, `secret.ts`, прав в друзьях и группах, OAuth, CalDAV — ещё `/security-review`.
- Изменение задевает интерфейс (мини-апп, лендинг, нативные экраны) — ещё `/interface-review`, и для работы Codex тоже.
- Код писал я сам — ещё обзор Codex только на чтение (скилл `codex-review`). Код писал Codex — проверяю я: дифф целиком, проверки, ревью выше.
- `/lc-explore` — «злой пользователь» на локальном стенде после заметной фичи; `/click-path-audit` — перед релизом и после больших правок общего состояния. Их находки — падающие сценарии в `e2e/_explore` (в git не попадают). «Чинить» — задание Codex: перенести сценарий в настоящий тест, убедиться, что падает, исправить; результат проверяю я.

## Прод

- Готовую работу пушу в `main` сам, без вопроса: хук `pre-push` проверяет и деплоит (решение владелицы 30.09: «Всегда с мака пуш сам»; пока настоящих пользователей нет). Из копии — `E2E_PORT=5180 git push origin HEAD:main`.
- Схема базы: сначала миграция на прод через Supabase MCP `apply_migration` (совместимая с кодом, который ещё крутится), проверить таблицы, потом пуш. Если MCP отвечает «Invalid or expired requestState» — прошу владелицу переподключить коннектор Supabase в claude.ai; DDL через `execute_sql` не обхожу.
- Скиллы `.claude/skills/*` и `.mcp.json` коммичу обычными PR, как остальной код (решение владелицы 08.10). Новый скилл для кода — ещё ссылка `.agents/skills/<имя>` → `../../.claude/skills/<имя>`, чтобы его видел Codex; дизайн-скиллы и `grilling` Codex не отдаются.
