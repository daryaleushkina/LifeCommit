# /lc-review — панель ревью перед пушем фичи

Запускать перед пушем фичи **вместе со встроенным `/code-review`**: тот ищет общие ошибки, эта панель — нарушения правил LifeCommit (владение данными при секретном ключе Supabase, тихие сбои, правила тестов из CLAUDE.md, платформа Telegram). Не встраивать в `scripts/hooks/pre-push`: ревью агентами медленное и недетерминированное, а хук должен давать один и тот же ответ на один и тот же код.

Вызов этой команды — согласие владелицы на запуск Workflow.

## 1. Запуск

База: `$ARGUMENTS`, если пусто — `origin/main`.

Запусти Workflow `lc-review` с `args: { "base": "<база>" }` (объект, не строка). Если по имени не находится — `Workflow({ scriptPath: ".claude/workflows/lc-review.js", args: { "base": "<база>" } })`.

Что внутри (`.claude/workflows/lc-review.js`): сбор изменений относительно `merge-base(база, HEAD)` вместе с правками без коммита и новыми файлами → линзы параллельно (`lc-review-errors` и `lc-review-tests` всегда; `lc-review-access` при `worker/`, `supabase/`, `shared/`, `wrangler.jsonc`; `lc-review-ui` при `src/`) → склейка дублей → `lc-skeptic` пытается опровергнуть каждый HIGH/CRITICAL. Линза доступа снимает блокер только при уверенном опровержении, остальные — понижают неуверенно подтверждённое до рекомендации.

## 2. Итог — по-русски, коротко

- `NOTHING_TO_REVIEW` — так и сказать, на этом всё.
- Вердикт одной строкой: «можно пушить» (`APPROVE`) или «есть блокеры» (`CHANGES_REQUESTED`). Если `incomplete` — назвать линзы из `failedLenses` и сказать, что одобрения нет, потому что они не отработали; предложить перезапуск.
- Каждый блокер: `[ВАЖНОСТЬ] заголовок — файл:строка`, одной-двумя фразами суть (`proof`), исправление (`fix`), пометка скептика (`note`).
- Рекомендации — коротким списком, по одной строке, без подробностей.
- «Не проверено» — сводка `residualRisk` по линзам, если там что-то существенное (например, «RED не проверен механически»).

Ключевые блокеры перед показом проверь сама по коду: агенты могут ошибаться и после скептика.

## 3. Решение по каждому блокеру — кнопками

AskUserQuestion пачками по 4 вопроса (по вопросу на блокер), варианты:

- **Чинить** (Recommended, если блокер подтверждён скептиком) — исправить. Баг — сначала тест, который его ловит и падает, потом исправление (CLAUDE.md).
- **Оставить с пометкой** — не чинить; рядом с кодом комментарий, почему так задумано, чтобы следующее ревью не поднимало это снова.
- **Записать в HANDOFF** — не чинить сейчас; строка в «Что дальше» в `docs/HANDOFF.md` с файлом:строкой и сутью.

## 4. После исправлений

- Повторить `/lc-review` один раз — только чтобы убедиться, что блокеры закрыты и не появились новые. Больше двух кругов ревью не делать: оставшееся — снова кнопками.
- Дальше обычный путь: коммит и пуш, хук `pre-push` прогонит typecheck, покрытие, e2e, сборку и деплой.
