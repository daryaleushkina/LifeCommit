# LifeCommit — передача дел

## Что это

Мини-апп Telegram ([@LifeCommit_bot](https://t.me/LifeCommit_bot), имя бота — «LifeCommit»): привычки, цели и дела на каждый день, карта активности по дням, группы и друзья, в перспективе — челленджи. Пользователям не пишем «как в GitHub», «даже чуть-чуть засчитывается», «смотри, как зеленеет карта» (решение владелицы 03.10.2026: GitHub многим незнаком, карта — не причина ставить приложение). Важная аудитория — люди с СДВГ: минимум решений на экране, частичное выполнение засчитывается, никаких стриков и стыда.

Прямой конкурент — Challenger (https://t.me/ChallengerTgBot): дедлайны, ИИ-коуч, серии, соревнование. Наше отличие — бережность и совместные механики.

## Стек и устройство

- **Мини-апп:** React + Vite + TypeScript + `@tma.js/sdk-react` — `src/`.
- **Сервер:** один Cloudflare Worker на Hono — `worker/`: API (`api.ts`), проверка подписи Telegram (`auth.ts`), webhook бота (`bot.ts`), напоминания по cron раз в 15 минут (`cron.ts`), логический день (`day.ts`).
- **База:** Supabase Postgres. RLS включён на всех таблицах **без политик** — так задумано: доступ есть только у Worker'а по секретному ключу. Миграции — `supabase/migrations/`, применяются через Supabase MCP (и дублируются файлом в репозитории).
- **Общие типы** клиента и сервера — `shared/types.ts`.
- Мини-апп ходит только на свой Worker, не на `*.supabase.co` (риск блокировок в РФ).

Схема базы заложена под все этапы (подписки, команды, челленджи, жалобы), но используются пока `users`, `tasks`, `task_goals`, `task_logs`, `task_subtasks`, `task_templates`.

## Команды

```bash
pnpm db:start     # локальная Supabase в Docker (порты 554xx), накатывает supabase/migrations
pnpm dev          # http://localhost:5173 — мини-апп + Worker с подменённым Telegram, база — локальная
pnpm load         # k6 по локальному стенду (VUS=100 по умолчанию; не-localhost адрес скрипт не примет)
pnpm db:reset     # снести локальную базу и накатить миграции заново; db:stop — остановить
pnpm dev:prod     # то же, но с БОЕВОЙ базой (.dev.vars.prod) — только когда правда нужно
pnpm typecheck
pnpm lint         # oxlint с проверкой типов: правила хуков React, висящие и неверно переданные промисы (.oxlintrc.json)
pnpm test         # vitest: логический день, уровни карты, шаг кнопки, зачёт дел
pnpm eval:voice   # эталоны разбора голоса на НАСТОЯЩЕМ Gemini (worker/eval), каждый случай трижды; не в хуке
pnpm e2e          # Playwright: все экраны и действия как человек, iPhone (WebKit) и Android (Chromium) × светлая/тёмная,
                  # правила вёрстки и эталонные снимки (e2e/__screens__); -u — переснять эталоны, --project=ios-light — один
pnpm build
pnpm bot:setup    # webhook, кнопка меню, команды и описания бота
```

**Деплой — при пуше в `main`, двумя путями:**
- **С Мака** (включён хук `scripts/hooks/pre-push`, один раз: `pnpm hooks:install`): перед пушем на самой машине идут typecheck, unit-тесты, сквозные тесты `pnpm e2e` (хук сам поднимает локальную Supabase; без Docker пуш останавливается), сборка и `wrangler deploy`; упало — пуш отменяется. Сразу после деплоя — проверка живого прода (`scripts/postdeploy-check.mjs`, с 04.10.2026; только чтение, без секретов): главная отдаёт HTML со скриптом именно той сборки, что в `dist/`, скрипт — JavaScript, `/api/me` без подписи — 401, `/bot/webhook` без секрета — 403; повтор до 6 раз через 5 с, пока Cloudflare разносит новую версию. Не прошло — `wrangler rollback --yes` на предыдущую версию, пуш отменяется, `LOCAL_DEPLOYED_SHA` не пишется. Правило «фича без теста в прод не уходит» — в `CLAUDE.md`. Хук записывает SHA в переменную репозитория `LOCAL_DEPLOYED_SHA`, и GitHub Actions свою задачу пропускает — минуты не тратятся.
- **Из облачной разработки** (хука нет): деплоит GitHub Actions (`.github/workflows/deploy.yml`: typecheck, тесты, сборка, деплой, та же проверка прода с откатом). Одна минута на релиз.

`git push --no-verify` с Мака отдаёт деплой в Actions — это может только владелица в своём терминале: Claude это запрещено (`.claude/settings.json` и хук `.claude/hooks/block-no-verify.mjs`, 04.10.2026), как и прямой `wrangler deploy` мимо хука. Секреты репозитория: `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID`. Вручную: `pnpm run deploy`.

Секреты Worker'а лежат в Cloudflare: `TELEGRAM_BOT_TOKEN`, `SUPABASE_SECRET_KEY`, `TELEGRAM_WEBHOOK_SECRET`, `GEMINI_API_KEY`. Локально — `.env.local`, `.dev.vars` (локальная база) и `.dev.vars.prod` (боевой ключ Supabase), в git не попадают.

**Локальный стенд (01.10.2026, решение владелицы — только локальный, облачный staging позже).** Все 15 миграций накатываются на чистую базу без ошибок — схема воспроизводится по репозиторию. Замер на Маке (12 ядер): 100 пользователей, сценарий «вход → Сегодня → добавить дело → отметить → карта → календарь» — ~485 запросов/с, 0 ошибок, p95 365 мс; упирается в PostgREST (~6,5 ядра). Годится для сравнения «до/после правки», поиска медленных запросов и N+1; **не** отвечает на «сколько людей выдержит прод»: прод — бесплатный тариф Supabase (60 соединений, общий CPU, Франкфурт), без дороги из Вьетнама и не на сети Cloudflare. Для такого замера нужен второй бесплатный проект Supabase + Worker `lifecommit-staging`. Порты 543xx заняты другим локальным проектом (audioguide), поэтому у нас 554xx.

Скриншоты экранов вне Telegram: `node .claude/skills/telegram-mini-app/scripts/screenshot.mjs --url http://localhost:5173/` (нужен `pnpm dev`).

## Что сделано (v0.1, личное ядро)

- Заставка: крупный знак 3×3 (клетки загораются по очереди) и название LifeCommit; данные грузятся, пока она на экране. Вариант с git-терминалом убран 30.09.2026: перегружен и непонятен тем, кто не знает git.

Тап открывает редактор уже нужного вида; **выбора типа в редакторе нет**, вид у существующей привычки не меняется. Так решено после четырёх исследований 30.09.2026: приложения спрашивают либо намерение, либо способ отметки, но не смешивают их.
- «Сегодня»: дата и карточки привычек (полоса карты за 22 недели убрана 01.10.2026 по просьбе владелицы — карта только во вкладке «Я») в одну строку с круглыми кнопками отметки (`RoundBtn` в `src/components/TaskCard.tsx`): галочка у «делать»; карандаш (ввести число) и галочка (сделано целиком) плюс полоса прогресса у «считать»; крестик и галочка с вопросом «Получилось?» у «бросить» (после ответа вопрос сменяется счётом «N дней без этого»). Повторный тап по выбранной кнопке снимает отметку.

## Решения, которые нельзя терять

**Продукт**
- Логический день заканчивается в 04:00 по местному времени (настраивается).
- Карта: 4 уровня зелёного по **абсолютной** сумме выполненного за день (одно дело = до 1,0). Это выбор владелицы, не «% от плана».
- Цель стала легче — действует с завтра; сложнее — сразу. История целей хранится, прошлые дни не пересчитываются.
- Стриков нет. «Тяжёлого дня» (режима минимума) нет. Глобальной паузы нет — вместо неё дело откладывают в архив.
- «Бросить»: вопрос «Сегодня получилось?», ответ крестиком или галочкой; счётчик «N дней без этого» срыв не обнуляет. В редакторе можно указать «Последний раз» (`tasks.last_slip_on`): дни между этой датой и первым днём дела прибавляются к счёту (`cleanDaysBeforeStart` в `shared/types.ts`). На карту активности прошлые дни не попадают.
- У количества два действия: галочка (сделано целиком) и ввод числа (карандаш или тап по числу, только цифры). Кнопки «+N» нет; поле `tasks.step` и `autoStep` остались в коде сервера, но интерфейс их не использует.
- **Лимитов нет** (01.10.2026, решение владелицы: «пусть пока для всех всё бесплатно, кроме аудио»): `FREE_TASK_LIMIT = null` в `shared/types.ts`; проверки на сервере, в боте и в интерфейсе остались — вернуть лимит можно одним числом (было 5). Дневной лимит голоса (20) остаётся.
- Дела по умолчанию видны «Только мне».
- Слогана нет вообще.
- Донаты — через Tribute, не звёздами Telegram.

**Соцчасть (ещё не сделана, но решена)**
- Профиль открытый/закрытый, как в Инстаграме; подписки; приглашение по ссылке, поиск по @username, бот в групповом чате.
- «Команда» (не «кружок») = групповой чат с ботом, вступление кнопкой; карта команды и рейтинг по % своего плана.
- Реакции, «пнуть» раз в день, комментарии по настройкам; нужны блокировка и жалоба.
- Челленджи: своя цель, общий счётчик (простая шкала, **без сундука и уровней**), одинаковая цель, программа, парный квест недели, окно-доказательство, команда на команду. Публичные создаёт любой; автоскрытие после 3 жалоб + фильтр слов.

**Дизайн**
- Стиль A «Мягкий»: своя палитра (светлая и тёмная), шрифт Onest, токены — в начале `src/styles/app.css`.
- Поверх — матовое стекло (30.09.2026, вариант 1 из круга 12 на холсте): карточки, карта активности, поля и нижняя панель полупрозрачные (`--glass`, `--glass-edge`, `--glass-blur`), под ними мягкие цветные пятна фона (`--glow` на `body`; тело не прокручивается, поэтому пятна стоят на месте). В тёмной теме — тёмное стекло со свечением. Шторки остаются сплошными ради читаемости.
- Числа — обычные (пропорциональные) цифры, **не `tabular-nums`**: в Onest моноширинная «1» даёт дыру («1 46»). Разряды — через `t.num()` (`Intl.NumberFormat`): 146, 1 146, 25 546.
- Правило экрана: одно главное действие, 3–4 блока, без легенд и подписей-пояснений; второстепенное — за тапом.
- Осознанное отступление от скилла `telegram-mini-app`: свои hex-цвета вместо `--tg-theme-*` (его `check.sh` на это ругается — так и должно быть).

### Жалобы пользователей → автоматическая починка (допрос идёт, ничего не сделано)

**Задача владелицы:** человек сообщает о проблеме из приложения (кнопка) и боту (текст, голос, скриншоты); жалобы хранятся недолго; раз в час автоматическая сессия Claude Code берёт новые, очевидные баги чинит и выкатывает сама, спорное — изучает и предлагает варианты владелице. **Что изучено (два исследования, 03.10.2026):**
- **Главный риск — prompt injection через текст жалобы.** Известные случаи: вредный issue заставил агента GitHub MCP вынести приватные репозитории в открытый PR (2025); через заголовки issues угоняли токены у Claude Code Action / Gemini CLI / Copilot, через issue в триаже Cline украли npm-токен и выпустили поддельный пакет (2026). Правило «смертельной тройки» (Willison) / «Rule of Two» (Meta): в одной сессии нельзя одновременно приватные данные + недоверенный ввод + канал наружу; детекторы атак не спасают. Меры: **две ступени** — модель без инструментов превращает жалобу в сухую карточку (категория, пересказ, шаги, экран), агент с кодом сырой текст не видит; вырезать невидимые/bidi-символы и HTML-комментарии; у агента **нет прод-секретов**; уведомления людям — шаблонами от Worker'а, не свободным текстом агента; просьбы «покажи env / запусти / поменяй настройки» в жалобе → категория `suspicious` и вопрос владелице.
- **Антиспам:** личность только из проверенной initData / `from.id`; лимиты на человека (предложено 3 в час, 10 в сутки) и общий потолок на проект (~200 в сутки) — счёт в Postgres в той же транзакции, что вставка (Cloudflare Rate Limiting — только всплески, окно 10/60 с, приблизительный); повтор того же текста за сутки — счётчик, а не новая жалоба; текст ≤2000 символов, ≤4 вложения, картинка ≤5 МБ, голос ≤2 минут (длительность видна до скачивания); «тихий мут» (`feedback_muted_until`) за спам, у владелицы `/ban`, `/unban`; ответы «починили» — с паузами (Telegram: ~1 сообщение/с в чат, ~30/с всего).
- **Что прикладывать из приложения:** версия сборки (git sha), платформа, язык, тема, размер экрана, пояс, маршрут и открытая шторка, последние ~20 переходов, ошибки `onerror`/`unhandledrejection` со стеком, последние ~20 запросов к API (метод, путь, статус, время, request-id); **не** прикладывать initData, тела запросов, содержимое дел. Показать человеку «приложим: …».
- **Хранилище:** своя таблица в Supabase (`feedback`, вложения, кластеры похожих), не GitHub Issues (персональные данные в репозитории, куда пишет агент, — ровно вектор атаки; вложения через API не загрузить). Срок — 30 дней после закрытия (не больше 90 с подачи), удаление по расписанию; из бота хранить только `file_id`, голос — расшифровать и аудио не держать. Для Hearway — общий код, но **раздельные базы** (`file_id` привязан к боту). 152-ФЗ: данные граждан РФ формально должны храниться в РФ — общий риск LifeCommit (Supabase и Cloudflare за рубежом), жалобы его чуть увеличивают; текст жалоб уходит в API Anthropic.

**Просьба владелицы:** одной голосовой фразой (важно для СДВГ) ставить и себе — привычки и дела, — и в группы; нейросеть должна правильно понимать, кому что. Поводом стало утро 03.10: «…настроить ноутбук Алёне…» целиком легло в группу «Семья ❤️». Алёна там есть, поэтому маршрутизатор решил, что фраза про группу, и личный разбор вообще не запустил: он включался только при «себе / лично» или явном названии группы.

**Как теперь (`worker/voiceRoute.ts`):** у кого есть группы, фразу разбирает **один запрос** к модели. Модель видит строку «Today is …», говорящего, все его группы с участниками (до 10 групп и 30 имён; одинаковые названия различаются: «Семья (2)»), экран, с которого нажали микрофон («Opened from group»), и саму фразу после «Speech:». Каждый пункт она кладёт ровно в одно место: себе (`habits` / `todos`, правила общие с личным разбором — `OWN_RULES` в `voice.ts`) или в одну группу (`group_items` с полем `group` из списка — enum в схеме; «кто делает» — `GROUP_RULES` в `groupVoice.ts`). Правила по порядку: названная группа действует до «а себе / мне лично / в группу …»; если делает другой участник («Алёне погулять с собакой», «напомни Пете») — его группа; если говорящий делает что-то для человека или с ним («настроить ноутбук Алёне», «позвонить Алёне», «встреча с Костей») — своё дело; «всей семьёй / каждый / по очереди» — группа, к которой это подходит; с экрана группы — туда, кроме «себе»; во всех сомнительных случаях — себе. Название группы из ответа сверяется сначала точно, потом без эмодзи и регистра — но только если так похожа ровно одна группа («Семья ❤️» и «Семья» — разные). Если модель вернула группу не из списка или похожих несколько, дело не теряется: оно становится своим, его видно в списке. Групп нет — прежний личный разбор. Эвристики `groupsOf` / `namedPeople` и режим «Only for group» у разбора чата удалены; `askModel` возвращает `{ raw, by }`.

**Подсказка в шторке записи** (`VoiceSheet.tsx`): у кого есть группы, под примером строка «Для группы назови её: „в группу Семья: в субботу уборка, а себе — купить молоко“» (название первой группы без эмодзи). С экрана группы — «Сказанное пойдёт в группу „…“. Своё — после слова „себе“».

**Проверено:** unit (`voiceRoute.test.ts` — все ветки разбора ответа), API (`voice.int.test.ts` — один запрос, что видит модель, архивные и чужие группы не показываются, регрессия «ноутбук Алёне»), шторка (`VoiceSheet.test.tsx`), e2e (`groups.spec.ts`: подсказка → одна фраза → «Добавить всё» → своё на «Сегодня», групповое в группе; на iPhone микрофон дан через `test.use({ permissions })`). `pnpm eval:voice`: +9 случаев (`r-noutbuk`, `r-imena-ne-gruppa`, `r-vse-srazu`, `r-dve-gruppy`, `r-ekran-i-sebe`, `r-vsey-semyey`, `r-ya-v-gruppe`, `r-semya-emoji`, `e-flatmates`) — все 12 «микрофонных» зелёные трижды; ответ ~1,2–2,2 с. Полный прогон: **48 из 49** (было 39 из 40); красный — по-прежнему только `p-inj-date` (открытый пункт 1 выше), личный разбор и чат группы не просели.

**Не сделано / решить:** голосовое боту в личку (`bot.ts`) по-прежнему только личное — групп не знает; «мы с Алёной идём в кино» модель кладёт в общую группу мероприятием (законное прочтение, но спорное); «по выходным вместе убираться» — «кто-то один», а не «все» (правила режимов группы, не маршрута).
