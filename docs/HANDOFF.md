## Что это

Мини-апп Telegram ([@LifeCommit_bot](https://t.me/LifeCommit_bot)): ежедневные дела, карта активности как в GitHub, в перспективе — сообщество (друзья, команды, челленджи). Важная аудитория — люди с СДВГ: минимум решений на экране, частичное выполнение засчитывается, никаких стриков и стыда.

Прямой конкурент — Challenger (https://t.me/ChallengerTgBot): дедлайны, ИИ-коуч, серии, соревнование. Наше отличие — бережность и совместные механики.

## Стек и устройство

- **Мини-апп:** React + Vite + TypeScript + `@tma.js/sdk-react` — `src/`.
- **Сервер:** один Cloudflare Worker на Hono — `worker/`: API (`api.ts`), проверка подписи Telegram (`auth.ts`), webhook бота (`bot.ts`), напоминания по cron раз в 15 минут (`cron.ts`), логический день (`day.ts`).
- **База:** Supabase Postgres. RLS включён на всех таблицах **без политик** — так задумано: доступ есть только у Worker'а по секретному ключу. Миграции — `supabase/migrations/`, применяются через Supabase MCP (и дублируются файлом в репозитории).
- **Общие типы** клиента и сервера — `shared/types.ts`.
- Мини-апп ходит только на свой Worker, не на `*.supabase.co` (риск блокировок в РФ).

Схема базы заложена под все этапы (подписки, команды, челленджи, жалобы), но используются пока `users`, `tasks`, `task_goals`, `task_logs`, `task_subtasks`, `task_templates`.

## Команды

```bash
pnpm db:start     # локальная Supabase в Docker (порты 554xx), накатывает supabase/migrations
pnpm dev          # http://localhost:5173 — мини-апп + Worker с подменённым Telegram, база — локальная
pnpm load         # k6 по локальному стенду (VUS=100 по умолчанию; не-localhost адрес скрипт не примет)
pnpm db:reset     # снести локальную базу и накатить миграции заново; db:stop — остановить
pnpm dev:prod     # то же, но с БОЕВОЙ базой (.dev.vars.prod) — только когда правда нужно
pnpm typecheck
pnpm test         # vitest: логический день, уровни карты, шаг кнопки, зачёт дел
pnpm build
pnpm bot:setup    # webhook, кнопка меню, команды и описания бота
```

**Деплой — при пуше в `main`, двумя путями:**
- **С Мака** (включён хук `scripts/hooks/pre-push`, один раз: `pnpm hooks:install`): перед пушем на самой машине идут typecheck, тесты, сборка и `wrangler deploy`; упало — пуш отменяется. Хук записывает SHA в переменную репозитория `LOCAL_DEPLOYED_SHA`, и GitHub Actions свою задачу пропускает — минуты не тратятся.
- **Из облачной разработки** (хука нет): деплоит GitHub Actions (`.github/workflows/deploy.yml`: typecheck, тесты, сборка, деплой). Одна минута на релиз.

`git push --no-verify` с Мака отдаёт деплой в Actions. Секреты репозитория: `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID`. Вручную: `pnpm run deploy`.

Секреты Worker'а лежат в Cloudflare: `TELEGRAM_BOT_TOKEN`, `SUPABASE_SECRET_KEY`, `TELEGRAM_WEBHOOK_SECRET`, `GEMINI_API_KEY`. Локально — `.env.local`, `.dev.vars` (локальная база) и `.dev.vars.prod` (боевой ключ Supabase), в git не попадают.

**Локальный стенд (01.10.2026, решение владелицы — только локальный, облачный staging позже).** Все 15 миграций накатываются на чистую базу без ошибок — схема воспроизводится по репозиторию. Замер на Маке (12 ядер): 100 пользователей, сценарий «вход → Сегодня → добавить дело → отметить → карта → календарь» — ~485 запросов/с, 0 ошибок, p95 365 мс; упирается в PostgREST (~6,5 ядра). Годится для сравнения «до/после правки», поиска медленных запросов и N+1; **не** отвечает на «сколько людей выдержит прод»: прод — бесплатный тариф Supabase (60 соединений, общий CPU, Франкфурт), без дороги из Вьетнама и не на сети Cloudflare. Для такого замера нужен второй бесплатный проект Supabase + Worker `lifecommit-staging`. Порты 543xx заняты другим локальным проектом (audioguide), поэтому у нас 554xx.

Скриншоты экранов вне Telegram: `node .claude/skills/telegram-mini-app/scripts/screenshot.mjs --url http://localhost:5173/` (нужен `pnpm dev`).

## Что сделано (v0.1, личное ядро)

- Заставка: крупный знак 3×3 (клетки загораются по очереди) и название LifeCommit; данные грузятся, пока она на экране. Вариант с git-терминалом убран 30.09.2026: перегружен и непонятен тем, кто не знает git.
- «Чего я хочу?» — первый экран и первый шаг при добавлении привычки: три намерения с цветными плитками-иконками — «Делать регулярно» (`check`), «Считать что-то» (`count`), «Бросить» (`abstain`). Тап открывает редактор уже нужного вида; **выбора типа в редакторе нет**, вид у существующей привычки не меняется. Так решено после четырёх исследований 30.09.2026: приложения спрашивают либо намерение, либо способ отметки, но не смешивают их.
- «Сегодня»: дата и карточки привычек (полоса карты за 22 недели убрана 01.10.2026 по просьбе владелицы — карта только во вкладке «Я») в одну строку с круглыми кнопками отметки (`RoundBtn` в `src/components/TaskCard.tsx`): галочка у «делать»; карандаш (ввести число) и галочка (сделано целиком) плюс полоса прогресса у «считать»; крестик и галочка с вопросом «Получилось?» у «бросить» (после ответа вопрос сменяется счётом «N дней без этого»). Повторный тап по выбранной кнопке снимает отметку.
- Экран привычки (тап по названию, `src/screens/TaskDetail.tsx`): блок «сегодня» с теми же кнопками, ключевые числа, календарь месяца с числами (листается назад до месяца, когда привычка появилась), у «считать» — столбики за две недели с линией цели, у «бросить» — крупный счёт и «подряд сейчас / самый долгий период / раз было за месяц». Карандаш в шапке открывает редактор. История приходит одним запросом `GET /api/tasks/:id/history`, считается на клиенте чистыми функциями из `shared/stats.ts` (покрыты тестами).

В базе значение `limit` и его ветка в `log_score` оставлены — вернуть можно без миграции; сервер такие дела не создаёт.

Состояния «не понял», «микрофон недоступен» (кнопка «Открыть чат с ботом» — там голосовые работают), «не получилось» и «на сегодня хватит». В базу до «Добавить» ничего не пишется. Сервер: `POST /api/voice` — аудио на вход, ответ построчный (NDJSON): сначала `{text}`, потом `{actions}` — список действий, пока только `create_habit` (задел под «отметить» и «дело на день»); `POST /api/tasks/batch` — пачка с проверкой лимита 5 бесплатных; если не помещается всё, добавляются первые, остальные в списке бледные. **Дневной лимит — 20 разборов на человека** (таблица `voice_usage`, функция `take_voice_quota`, день по UTC), общий с сообщениями боту.
- **Разовые дела на день** (01.10.2026): блок «Дела» над привычками на «Сегодня» (`src/components/TodoList.tsx`, логика — `src/useTodos.ts`). Кружок слева — сделано (зачёркивается и опускается вниз, повторный тап снимает), тап по названию — шторка `TodoSheet` (название, «Сегодня» / «Завтра» / «Другой день» — календарь не раньше послезавтра, «Удалить дело»). Строка «+ Дело на сегодня» превращается в поле: Enter добавляет и оставляет поле открытым для следующего. Несделанное **тихо переезжает** на следующие дни: `todos.day` не меняется, интерфейс пишет «со вчера» / «с 26 сентября» — без красного и «просрочено». Запланированные на потом — ссылка «Потом · N» → шторка по дням (список грузится только при открытии). Сделанное дело зеленит карту как привычка (1.0 за дело — в `user_heatmap` и в `heatWithToday`). База: таблица `todos` (миграция `20261001000003_todos.sql`), API `POST /todos`, `/todos/batch`, `PATCH|DELETE /todos/:id`, `GET /todos/later`. Лимита на дела нет.

Внизу: Сегодня · Календарь · 🎤 · Я (`src/screens/Calendar.tsx`): «День / Месяц» (неделю владелица заменила на день: ‹ день › и «К сегодня»), в месяце точки под днями (до трёх несделанных; синие — из календаря телефона), ниже — дела выбранного дня. В шапке: «обновить» (только обновляет, крутится, пока идёт; виден, когда календарь подключён) и шестерёнка — шторка «Календари» (`TodoList` с заголовком-датой; в прошедший день добавлять нельзя). У дела необязательное **время** (`todos.time`; в шторке строка «Время», пусто — «Весь день»; голос понимает «в 15:00», «завтра в девять утра»); дела со временем идут первыми по часам (`sortTodos` в `shared/types.ts`), у событий видно «до 11:00» (`duration_min`). **Повторяющиеся дела** — одна строка с `rrule` (RFC 5545), дни считает `shared/rrule.ts` (тесты: дни рождения, «2-й вторник», последняя пятница, 29 февраля, COUNT/UNTIL/EXDATE); «сделано» — на каждый день отдельно (`todo_done`), карта считает и их. API: `GET /api/calendar?from&to` (до 62 дней), `PATCH /todos/:id` принимает `time` и `on` (день отметки повторяющегося). Поля для синхронизации уже в базе: `source`, `external_uid`, `external_href`, `external_etag`, `calendar_url` (миграция `20261001000004`). Свои несделанные дела переезжают на следующий день, дела из календаря — нет (прошедшая встреча не «со вчера»).
- **Синхронизация с Apple Календарём в обе стороны** (01.10.2026; на настоящем iCloud ещё не проверена — проверена на локальном CalDAV-сервере Radicale). Подключение: вкладка «Календарь» → плашка «Подключите календарь» или значок обновления → шторка «Календари» (`src/components/CalendarsSheet.tsx`) → Apple: три шага про пароль приложения (appleid → «Вход и безопасность» → «Пароли приложений»), почта Apple ID и пароль. Сервер: `worker/caldav.ts` (CalDAV: поиск календарей, `sync-collection` RFC 6578, `calendar-multiget`, PUT/DELETE с ETag; XML разбирается по тегам — DOMParser в Workers нет), `worker/ics.ts` (iCalendar: часовые пояса через Intl, RRULE, EXDATE, изменённые и отменённые разы — RECURRENCE-ID → отдельное дело + исключённый день), `worker/calsync.ts` (сама синхронизация), `worker/secret.ts` (пароль приложения в базе только зашифрованным AES-GCM; ключ — секрет Worker'а `CALENDAR_KEY`, заведён 01.10.2026). Таблицы `calendar_accounts`, `calendar_collections` (миграция `20261001000005`). Правила: все события из всех календарей становятся делами (`source='apple'`, метка «A»); разовые старше 30 дней не забираем; наши дела **только со временем** пишутся в календарь событиями с UID `lifecommit-<id>` (дела без времени в Apple не уходят — решение владелицы 01.10.2026: «Напоминания» Apple с iOS 13 закрыты для сторонних приложений, CalDAV их не видит, а событие «на весь день» её не устроило; время дали — событие появляется, убрали — удаляется; выгруженные раньше без времени чистятся при синхронизации) — по нему узнаём свои и не задваиваем; правка дела из календаря меняет само событие (только название и время, повтор и напоминания остаются); удаление с любой стороны удаляет на другой (у повторяющегося — всю серию); «сделано» в календарь не уходит. Когда: наши правки — сразу (`waitUntil` после запроса), из календаря — при открытии вкладки и по кнопке (не чаще раза в минуту, `POST /api/calendars/sync`) и cron раз в 15 минут (по 4 подключения за запуск, кого дольше не обновляли). Пароль перестал подходить — статус `auth_failed`, в шторке «Ввести новый пароль». Отключение убирает пришедшие дела, наши остаются. ## Решения, которые нельзя терять

**Продукт**
- Логический день заканчивается в 04:00 по местному времени (настраивается).
- Карта: 4 уровня зелёного по **абсолютной** сумме выполненного за день (одно дело = до 1,0). Это выбор владелицы, не «% от плана».
- Цель стала легче — действует с завтра; сложнее — сразу. История целей хранится, прошлые дни не пересчитываются.
- Стриков нет. «Тяжёлого дня» (режима минимума) нет. Глобальной паузы нет — вместо неё дело откладывают в архив.
- «Бросить»: вопрос «Сегодня получилось?», ответ крестиком или галочкой; счётчик «N дней без этого» срыв не обнуляет. В редакторе можно указать «Последний раз» (`tasks.last_slip_on`): дни между этой датой и первым днём дела прибавляются к счёту (`cleanDaysBeforeStart` в `shared/types.ts`). На карту активности прошлые дни не попадают.
- У количества два действия: галочка (сделано целиком) и ввод числа (карандаш или тап по числу, только цифры). Кнопки «+N» нет; поле `tasks.step` и `autoStep` остались в коде сервера, но интерфейс их не использует.
- **Лимитов нет** (01.10.2026, решение владелицы: «пусть пока для всех всё бесплатно, кроме аудио»): `FREE_TASK_LIMIT = null` в `shared/types.ts`; проверки на сервере, в боте и в интерфейсе остались — вернуть лимит можно одним числом (было 5). Дневной лимит голоса (20) остаётся.
- Дела по умолчанию видны «Только мне».
- Слогана нет вообще.
- Донаты — через Tribute, не звёздами Telegram.

**Соцчасть (ещё не сделана, но решена)**
- Профиль открытый/закрытый, как в Инстаграме; подписки; приглашение по ссылке, поиск по @username, бот в групповом чате.
- «Команда» (не «кружок») = групповой чат с ботом, вступление кнопкой; карта команды и рейтинг по % своего плана.

**Дизайн**
- Стиль A «Мягкий»: своя палитра (светлая и тёмная), шрифт Onest, токены — в начале `src/styles/app.css`.

## Что можно оптимизировать уже сейчас

**Скорость ответа сервера** — пункты 1–5 сделаны 01.10.2026:
- Smart Placement включён (`"placement": { "mode": "smart" }` в `wrangler.jsonc`). Cloudflare переносит исполнение не сразу, а по накопленной статистике запросов; эффект — смотреть по времени ответов в Observability через день-два.
- `/api/today` — один вызов SQL-функции `today_screen` (миграция `20261001000001_today_screen.sql`) вместо трёх кругов и N+1 на «бросить». Вместе с чтением пользователя — 2 запроса к базе на экран. Локально (Вьетнам → Франкфурт) ответ ~0,9 с.

- Редактор и «Отложенные» берут данные из кэша, без запроса `/today`.
- «Сегодня» не перечитывает данные при возврате на экран, если им меньше минуты (раньше — сразу после заставки и после каждого редактора).

**Загрузка приложения**
6. **Шрифт Onest со своего сервера**, а не с `fonts.googleapis.com`: из России Google-домены бывают медленными или недоступны, и тогда текст мигает запасным шрифтом. Положить `woff2` в `public/` — минус один внешний домен на старте.
7. **Разделить сборку.** Один JS-файл 340 КБ (≈100 КБ в gzip). Экраны привычки, профиля, редактора и шторки можно грузить лениво (`React.lazy`) — «Сегодня» откроется быстрее. Выигрыш небольшой, делать после пунктов 1–4.
8. **Стекло на слабых телефонах.** `backdrop-filter` стоит на каждой карточке. Если на телефоне прокрутка подтормаживает — оставить размытие только у нижней панели и карты, а карточкам дать полупрозрачную заливку без размытия.

**Масштаб и деньги**
9. **Cron напоминаний читает всех пользователей с напоминаниями каждые 15 минут** и фильтрует время в коде (`worker/cron.ts`). На тысячах пользователей это лишняя нагрузка — выбирать в SQL только тех, у кого местное время попало в окно.
10. **Лимит голоса на человека.** Квоты Gemini и Workers AI (10 000 нейронов в день) общие на всех — один активный человек может выбрать их за всех. Нужен счётчик разборов в день (например, 20) в таблице или KV.
11. **История привычки обрезается на 1000 отметок** (`/api/tasks/:id/history`). Сейчас это почти три года ежедневных отметок — хватит надолго, но для статистики «за всё время» лучше считать итоги в SQL, а не тянуть все строки.
12. **Supabase на бесплатном тарифе засыпает** после 7 дней без активности; сейчас его будит cron. К запуску — тариф Pro или отдельная проверка «живости».

## Грабли

- В `pnpm dev` React StrictMode запускает загрузку дважды: второй ответ может на секунду вернуть старое значение только что отмеченного дела. В проде загрузка одна.
- Отметить привычку можно с двух экранов, а ответы сервера приходят не по порядку, поэтому устаревание ответов отслеживает общий на приложение счётчик (`currentChange` / `bumpChange` в `src/useTaskLog.ts`): фоновое обновление, начатое до изменения, свой результат выбрасывает.
- Голос работает на **Cloudflare Workers AI** (привязка `AI` в `wrangler.jsonc`): речь — `@cf/openai/whisper-large-v3-turbo`, запасной — `@cf/openai/whisper`. Разбор фразы на привычки — сначала **Gemini** (`gemini-flash-lite-latest`, бесплатный уровень; ключ из Google AI Studio, аккаунт darya.leushkina@gmail.com, отдельный проект Google Cloud «LifeCommit», секрет Worker'а `GEMINI_API_KEY`), ответ ждём 12 секунд; если Gemini упал или не успел — `@cf/meta/llama-3.3-70b-instruct-fp8-fast` в Workers AI. У обеих моделей одна JSON-схема и два примера. На бесплатном уровне Gemini отвечает 3–9 секунд и бывает перегружен (503), а тексты запросов Google может использовать для улучшения моделей. Бесплатно 10 000 нейронов в день на аккаунт (минута речи ≈ 47), на бесплатном тарифе сверх лимита запросы падают. **Whisper turbo ненадёжен:** 01.10.2026 он отвечал «Failed to decode audio file» на две трети исправных файлов (OGG, webm, mp4 — одинаково; и строкой base64, и потоком). Поэтому в `transcribe` одна попытка turbo, затем старый `@cf/openai/whisper` (до двух попыток) — на тех же файлах 18 из 18. Цена у обоих ~41 нейрон за минуту речи; `@cf/deepgram/nova-3` тоже 18 из 18 и точнее («спортзал», а не «спортсал»), но в 10 раз дороже — на бесплатных 10 000 нейронов это ~21 минута речи в день на всех. Проверить только распознавание: `POST /bot/dev-voice?parse=0`. Не гонять разбор параллельно — бесплатный Gemini отвечает 429 на поминутный лимит.
